# Live2D 服装来源

主题自带 Tia、Pio 各三套基础服装。在「主题设置 → 看板娘」选择模型及一种服装来源，保存后刷新前台。桌面窗口至少861px时加载模型，使用原来的「换装」按钮。

| 来源 | 使用方式 |
| --- | --- |
| jsDelivr CDN（默认） | 自动关联模型，按需加载服装，无需填写地址或上传图片。 |
| 已下载到本站 | 点击「下载到本站／继续下载」，完成后保存设置。 |
| 仅内置服装 | 只使用模型自带的三套服装。 |
| 自定义外置清单 | 使用下方协议手动部署自己的JSON与PNG。 |
| 旧版远程PNG接口 | 使用原接口基址，自动追加模型名；此处不能填JSON地址。 |

五种来源互斥。升级时已有自定义清单或旧远程接口的站点会保留原选择；没有旧配置才默认CDN。旧远程复选框已并入来源选择。

## 自动关联与本站下载

当前Pio扩展库包含104套服装，加上三套内置共107种；Tia尚无经过验证的兼容扩展，自动使用自己的内置服装，不能套用Pio纹理。

CDN使用安装包对应的固定源码提交。没有构建来源的开发副本不会推测未发布地址，会保留内置服装并在后台提示。首屏仍只显示一张内置纹理，CDN扩展图片仅在换装选中时读取，不预下载整库。

jsDelivr也支持固定版本标签，地址格式为 `https://cdn.jsdelivr.net/gh/ADDGM/sakura@<版本标签>/live2d/costumes/pio/textures/<文件名>.png`。标签必须指向包含这些资源、且与安装包清单一致的提交；旧标签不会自动获得新服装目录。默认使用完整提交SHA即可固定版本，无需站点维护者手动修改链接。标签和SHA都不要求把图片装进主题ZIP，安装包排除规则与CDN资源版本独立处理。

本站下载为主动操作，Pio扩展PNG合计50,456,340字节（约48.12MiB）。每个请求使用HTTP Range读取256KiB，单张图片也能断点续传；服务器不支持Range时，可接收并校验有界的完整文件。暂停会等当前请求结束，可关闭页面后继续；文件完整后才核对大小、SHA-256及PNG格式并安装。完成后界面选中「已下载到本站」，需要保存设置才生效；下载期间请等待完成或暂停后再保存。需要PHP服务器能够连接jsDelivr，以及上传目录有足够空间和写入权限。

下载失败后可再次点击「下载到本站／继续下载」恢复。需要全部重新获取时使用「覆盖重新下载／继续」，重下进度也会保留；已有图片先保留，新图验证成功才替换。「清除未完成下载」会删除当前托管版本的分片和未启用的下载内容；已启用的完整库、自定义上传目录和其他版本不受影响。完整性校验失败的分片会丢弃，下一次从该文件开头重试。

资源保存在WordPress上传根下的 `sakura-live2d/managed/<模型>/<清单指纹>/`，自动适配子目录、多站点和自定义上传根，不需要手填服务器路径。只有全部文件通过大小、SHA-256与PNG检查才启用本地库；不完整时保留内置服装。下载与主题目录分离，更新主题不删资源；请将上传目录纳入备份。新清单内容对应独立版本目录，旧版本由维护者在用毕后清理。使用中被外部工具删改的PNG会在下一次下载检查时重新发现；前台单张失败保留当前外观。

## 维护仓库资源

```text
live2d/costumes/pio/
  catalog.json
  textures/<小写ASCII名称>.png
```

原根级107PNG已按模型归入此处，括号颜色名改为短横线，图片字节不变。三份内置重复内容留作原始集合的一部分，但不加入扩展清单。`catalog.json`由以下命令生成和检查；生成器拒绝未经重新兼容性验证的模型指纹变化。

```bash
node scripts/build-live2d-costumes.cjs
node scripts/build-live2d-costumes.cjs --check
```

PNG保留在Git仓库和源码归档中供CDN访问；CI与Release构建仅在生成主题安装载荷时排除扩展图片目录，模型清单与管理代码仍进入安装包。请安装CI或Release提供的主题包，GitHub自动生成的源码ZIP包含完整服装资源。新目录提交发布后才能通过该提交的CDN地址读取；本地重命名不会自动更新CDN。模型映射与历史来源记录见[服装调查](../.agents/notes/proposed/feature/2026-10-17-live2d-costume-catalog.md)。

## 自定义清单部署

1. 在「主题设置 → 看板娘」选择模型，将「服装来源」设为「自定义外置清单」。
2. 通过 SFTP 或主机文件管理器，在站点上传目录下的 `sakura-live2d/` 中放置文件。默认目录是相对于 WordPress 安装目录的 `wp-content/uploads/sakura-live2d/`，不是服务器磁盘绝对路径，也不固定以 `/sakura/` 开头。自定义上传目录或多站点以站点配置为准；后台说明只显示通用目录和固定的 `example.com` 示例，不展示服务器磁盘路径或本站网址。

   ```text
   wp-content/uploads/sakura-live2d/pio/pack-v1/
     catalog.json
     textures/
       outfit-a.png
       outfit-b.png
   ```

3. 按下方格式创建清单，填写完整清单 URL 并保存。示例中的 `example.com` 和上传路径必须替换为实际部署地址，不要直接填入占位网址。在大于等于 861px 的桌面窗口刷新前台，使用原来的「换装」按钮。
4. 更新服装时上传到新版本目录（例如 `pack-v2`），同步 `packVersion`，验收后修改清单 URL。旧目录待旧页面与缓存不再使用后自行清理；将服装目录纳入备份。

```json
{
  "version": 1,
  "packVersion": "v1",
  "model": {
    "id": "pio",
    "sha256": "1545fdb296bb2d1c9c6f1c295b3a336705618aa467c45e9be8dbc9cb1ffb704d"
  },
  "costumes": [
    {"id": "outfit-a", "texture": "textures/outfit-a.png"},
    {"id": "outfit-b", "texture": "textures/outfit-b.png"}
  ]
}
```

示例 PNG 文件名是占位名，需替换为你已准备好且适配该模型的图片。清单只声明模型兼容性，主题不会凭图片内容证明其适配性或来源。Tia 与 Pio 的纹理不能混用。

| 模型 | 当前 `model.moc` 的 SHA-256 |
| --- | --- |
| Pio | `1545fdb296bb2d1c9c6f1c295b3a336705618aa467c45e9be8dbc9cb1ffb704d` |
| Tia | `f19c7a20bf7eafcc1ef303b9c9c52d0face97aa0990129aeddec8d5e089d1ef5` |

更换模型文件后须重新检查兼容性并更新清单指纹；前台使用安装中的模型文件计算出的指纹校验。

## 格式与访问要求

- 清单为 UTF-8 JSON，格式 `version` 固定为数字 `1`，最大 64 KiB、256 项。包版本和服装 ID 为 1–64 个英文字母、数字、点、下划线或短横线，首字符为字母或数字。
- `texture` 为清单所在目录下的相对 PNG 路径，最长 240 字符。每段只用英文字母、数字、点、下划线或短横线，首字符不能为点。不接受绝对路径、`..` 路径段、反斜杠、百分号编码、查询参数或片段。
- 重复路径/相同条目只加入一次；同一 ID 指向不同路径、任何非法条目、未知格式或模型不匹配，整份清单不接入。空清单保持内置服装。
- 清单地址须为完整 HTTP(S) URL，路径以 `.json` 结尾，可有稳定查询参数，不含账号密码或片段；直接返回 JSON，不使用重定向。HTTPS 页面须使用 HTTPS 资源。
- CDN 的 JSON **和 PNG** 都需提供允许本站读取的 CORS 响应头，例如公开静态资源使用 `Access-Control-Allow-Origin: *`。图片能在地址栏打开不代表可用于 WebGL。遵循本站 CSP 的 `connect-src` 和 `img-src` 配置。
- 给版本化文件设置适当的 `Cache-Control`；更改内容时换目录/URL。`packVersion` 用于标识包，不会自动给图片加随机参数，也不自动刷新旧缓存。CORS 修正后若旧响应仍被缓存，应清理缓存或更换版本 URL。

## 运行与故障处理

先显示内置模型，后台读取清单，首次显示不会预下载扩展 PNG。每次换装只加载选中图片，已经访问的固定 URL 可由浏览器缓存。清单请求超过 10 秒、404、格式/CORS 错误时继续使用内置服装；图片超过 15 秒或加载失败时保留当前纹理，可再次换装重试。图片尺寸不得超过设备的 WebGL 纹理上限。

保存非法地址会提示错误并保留原值；保存时不探测网络，因此仍需前台验收地址是否可访问。清单失败后可刷新页面重试。自定义模式下留空清单配置即可停用扩展服装；自定义目录由维护者保管，后台下载器只处理主题注册的服装库，不修改自定义素材。

后台下载器只接受所选模型的受信清单，不接受任意URL或ZIP导入。

## 关于主题上传大小

自托管 WordPress 没有各站通用的“50 MB主题上限”。[后台上传值](https://developer.wordpress.org/reference/functions/wp_max_upload_size/)受 PHP 的 `upload_max_filesize`、`post_max_size` 和站点过滤器影响，Web 服务器及托管平台还可能限制请求体。后台「媒体 → 添加」可查看 WordPress 显示值；主题 ZIP 上传是否成功还取决于服务器实际配置。

WordPress.org 主题目录的投稿是另一个入口：截至 2026-10-17，[官方上传源码](https://github.com/WordPress/wordpress.org/blob/trunk/wordpress.org/public_html/wp-content/plugins/theme-directory/upload.php)设置的是 `10 * MB_IN_BYTES`，不能据此推定个人站点的上限。

把图片单独存放能让主题 ZIP 大小不随服装数量增加。通过同一后台上传入口传独立 ZIP 仍受上传限制；SFTP/主机文件管理器是否有额外限制，取决于服务商。
