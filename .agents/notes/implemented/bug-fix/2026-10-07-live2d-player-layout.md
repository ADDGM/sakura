# Agent Note: Live2D 保存位置与播放器可见区域避让

Status: implemented

## Problem

固定播放器、列表和歌词会与 Live2D 交互区重叠。拖动控件还可能进入页头遮挡区；按整块透明歌词容器计算避让，则会在播放器收起后保留无必要的 40px 上移。必须区分用户保存的位置与临时显示偏移，避免布局修正改变用户选择。

## Decision

[message.js](../../../../live2d/js/message.js) 将用户位置保存在 `sakura-live2d-position`，默认 `left=30`、`bottom=0`，另用 `playerOffset` 表示临时避让。`updatePlayerOffset()` 始终以保存位置和实际相交区域计算，`applyPosition()` 只应用显示边界与偏移，不把动画中的 CSS 值作为下一轮计算基准。

`getBounds()` 限制视口范围，并为可见 fixed/sticky 页头及 WordPress 管理栏预留顶部空间。拖动使用独立手柄，支持鼠标、触摸、键盘和重置，不占用模型点击区域；历史位置显示时限位，播放器展开收起不覆盖保存位置。

`getPlayerRects()` 对播放器本体与列表使用可见矩形，对歌词使用 DOM Range 的文字矩形并裁切到歌词窗口，忽略空白、透明及窗口外文本。歌词容器横跨视口不代表整块区域都需要避让；收起后若可见文字确实仍与模型相交，继续避让是正确行为，不能把任意场景都断言为 `bottom=0`。

[sakura-app.js](../../../../js/sakura-app.js) 复用 `notifyLive2DPlayerLayout()`，在点击、悬停、过渡结束，以及 `timeupdate`、`lrcshow`、`lrchide` 时通知更新；现有 350ms 延后重算覆盖过渡。使用已有事件和清理机制，不因这次修复增加观察器或持续轮询。

## Alternatives considered

- **整块歌词容器作为障碍**：矩形计算直接简单，但原实现实测在自然收起后仍产生 40px 残余；透明容器覆盖视口不能代表文字实际覆盖，因此改为可见文字范围。
- **按文字范围计算（采用）**：保留歌词显示且能识别真实相交；代价是多一次文字矩形测量，并依赖字体、换行与过渡时序。

原页头修复记录明确保留浮层层级、通过位置边界避让，但未给出完整的层级方案比较；本篇不补造其历史否决理由。早期测试中手动隐藏歌词/列表属于掩盖复现的夹具行为，不作为产品方案保留。

## Consequences

用户保存位置与临时偏移分离，控件保持可达，歌词仍显示。有限视口可能无法容纳所有浮层，顶部边界优先于无限上移；不同字体和播放器尺寸仍需要实际页面验证。测试应等待动画结束，避免用重置、人工重算或隐藏歌词掩盖自然收起问题。

## Historical regression evidence

2026-10-06用户部署dev.74/c7ee80b后，六份关键JS/CSS与该提交一致（比较仅规范化换行），11项直接前台检查通过，包含边缘限位、PNG延迟、860/861冷加载，且未替换脚本或注入CSS。但收起后通过重置恢复默认，未验证自然收起；早期本地测试又人工隐藏歌词/列表，不能用这些通过记录否认随后发现的收起残余问题。

收起残余问题在原部署自然收起750/1500ms仍为40px，手动重算也不恢复；本体已收回right18，剩余是宽1280、高30的透明歌词容器。移除隐藏/重算后回归先失败40 !== 0，修复后26项浏览器与19项Node通过。临时本地JS替换得到展开66、自然收起0，属于修复验证；用户部署dev.75/20dd904后才用服务器原脚本确认两轮收起750/1500/900ms均0，歌词仍可见且有文字，无替换、重置或人工重算。350ms仍在正常过渡，不作为失败。

当时独立浏览器和路由均关闭；dev.74记录的外部MP3 ERR_ABORTED未被证明是播放器故障，也没有实际点击播放。上述版本限定的结论来自已核对的报告与before/after/deployed JSON，原始图像和脚本已经退役，当前可见文字真正相交时仍应避让。
