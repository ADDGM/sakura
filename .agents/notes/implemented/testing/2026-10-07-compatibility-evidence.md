# Agent Note: 兼容性桥接的分层验证与证据范围

Status: implemented

## Problem

旧主题跨到新版WordPress/PHP后，语法通过仍可能在登录态、外部API、页面替换或真实部署中失败。烟雾测试自身也曾因字符串插值、换行及过期源码断言失败，需要区分测试夹具故障和主题缺陷。

## Decision

沿用兼容性桥接：保留设置键、主题模板和REST入口，以边界保护及局部修复维持既有行为；不将兼容升级扩大为主题重写。当前[ci.yml](../../../../.github/workflows/ci.yml)同时保留PHP8.0/8.1/8.2构建与WordPress7.0/7.1乘三PHP版本的六组smoke。

上述桥接是原阶段的迁移依据。维护者于2026-10-15明确按重构升级整理低于支持基线的分支，[当前运行基线](../architecture/2026-10-15-supported-runtime-cleanup.md)与[音乐旧协议退役](../simplification/2026-10-15-music-token-only.md)部分接管旧路径保留策略；现用设置、模板和其他接口边界继续有效。不能将六组矩阵的历史成功直接作为后续改动已重验的证据。

[scripts/wordpress-smoke.php](../../../../scripts/wordpress-smoke.php)组合源码契约与已加载WordPress的运行时检查。PHP lint、脚本自测、静态字符串存在性、模拟上游响应、真实站点浏览器验收是不同证据：不能由源码标记或模拟成功推导实际第三方可用、邮件送达、图床上传或WebGL渲染成功。

需要字面匹配的PHP变量保留字面量；源码检查时规范化CRLF，真实文件不因检查改写。实现契约变化时同步旧断言，先定位失败归属，不能为消除红灯直接删除保护。

后台颜色控件退役主题副本后，验证职责随实现迁到WordPress原生资源的注册、依赖与入队；不继续要求主题声明宿主的翻译字符串。smoke临时切换主题设置页screen并补注册原生后台脚本，检查主题入队前后的核心依赖对象、主题脚本依赖和样式队列，再恢复screen及其文章/分类上下文。HLS本地请求地址已有[HLS行为测试](../../../../scripts/tests/hls.test.cjs)直接验证，PHP smoke不重复绑定JavaScript字符串的引号格式，继续检查包内运行时文件和旧上游地址禁用规则。

翻译PO是编辑入口，MO由[仓库PHP编译器](../../../../scripts/compile-translations.php)生成，CI同时运行 --self-test 和 --check。编译支持上下文/复数，跳过fuzzy、obsolete及空翻译，空译文回退原文；不能仅凭MO可读取就认定它与PO及当前编译器一致。

MO不生成哈希表时，头部仍记录空哈希表的实际起点（紧接译文索引、与字符串区起点一致）。2026-10-11首页视频翻译验收发现，原来的零偏移可被Python gettext容忍，但WordPress POMO用该位置计算译文索引长度，会拒绝导入。采用有效空表偏移，保持现有轻量编译器；不因新版WordPress使用更宽容的读取器而放弃POMO兼容，也不增加外部gettext依赖。smoke通过真实WordPress MO导入四语言并查验新增译文，PO/MO一致性仍由编译器检查。

部署回归需写清版本、入口、登录状态、视口及网络条件。动态漂亮链接落到Nginx错误页时先区分服务器路由和主题404；实际图片上传需要独立验证，不能由前端布局或模拟接口通过来推定。

分类图片初始化的[独立回归](../../../../scripts/tests/categories-images.php)使用PHP进程加载真实模块，仅替代WordPress选项读取和钩子注册接口。测试把包括弃用提示在内的PHP诊断作为失败，检查缺失/非数组配置的回退、有效排除列表的钩子行为，以及初始化不写回选项；接入既有三版本PHP构建检查。它补充WP-CLI smoke未触发的后台初始化路径，不代表真实后台心跳或数据库集成已经复验。

## Alternatives considered

- 完整现代化重写：可以系统清理旧架构，但原计划选择桥接以保留设置和外部接口，先验证已确认的兼容风险。
- 只做PHP8.2静态检查：原草稿范围较小、执行成本低，但覆盖不到其他目标PHP和WordPress运行时；当前采用三PHP、六组WordPress矩阵，再按变更补实际场景。
- 复用任何工具生成的MO：历史出现“文件可反编译但二进制不一致”的失败，当前要求使用仓库编译器及同步检查。
- 仅删除升级后失效的四条源码断言：能消除误报，但后台原生依赖会缺少对应保护，因此以真实WordPress资源注册与依赖检查接管；HLS地址复用已有行为测试，不再增加重复字符串匹配。
- 仅在完整WordPress smoke中验证分类图片初始化：能覆盖宿主真实选项API，但需准备数据库且原smoke没有触发后台初始化。该缺陷可由真实模块接收`false`直接复现，因此增加无外部依赖的行为回归；实际部署后的后台日志仍须独立核对。

## Consequences

失败可按层定位，旧配置和部署证据可追溯；代价是矩阵与实站检查的维护成本。源码契约仍会随实现变化而漂移，stub不会证明外部服务健康，目标版本矩阵也不代表所有插件组合受支持。

## Category image initialization 2026-10-12

## Login header compatibility 2026-10-15

2026-10-13隔离登录页记录到主题注册`login_headertitle`引起的弃用提示。WordPress自5.2起推荐[login_headertext](https://developer.wordpress.org/reference/hooks/login_headertext/)，用于登录页Logo链接的文本；[旧钩子](https://developer.wordpress.org/reference/hooks/login_headertitle/)仍经过弃用分派。[login_header源码](https://developer.wordpress.org/reference/functions/login_header/)先兼容旧钩子，再应用新钩子，最后直接输出链接文本。

[主题回调](../../../../functions.php)改为注册`login_headertext`，并使用`esc_html`转义站点名称；保留回调名和既有`login_headerurl`首页链接。只移除品牌回调虽然最简单，但会丢失站点名称；保留旧钩子并屏蔽诊断也无法解决弃用根因。主题最低WordPress7.0已覆盖新接口，不增加旧版本分支。此次只处理该钩子及文本输出上下文，登录页脚本和验证逻辑留在各自范围。

PHP8.2.33对`functions.php`语法检查通过；将本次三行改动在内存中还原后，文件SHA-256与上一轮交付清单一致，确认保留了既有未提交工作。本地阶段依据官方接口与源码核对注册和输出上下文，没有为这个局部替换重建WordPress或新增重复注册断言，也未将静态检查表述为运行时日志已经消警。
