# Agent Note: 看板娘通过纹理替换完成一键换装

Status: implemented

## Problem

现有本地服装只在整页加载时随机选择，用户希望直接在看板娘上换装。反复调用 `loadlive2d` 会重新加载模型与动作，不能把一次纹理变化变成整套运行时重新初始化。

## Decision

维护者2026-10-17提出换装按钮。[页脚按钮](../../../../footer.php)与拖动、重置、隐藏共用控件区，使用原生 button、可访问名称及状态通知；模型就绪且存在可换资源时显示，忙碌期间禁用。[控制器](../../../../live2d/js/costume.js)通过原有 WordPress 依赖链在运行时、提示模块之后及 loader 之前加载。

本地从当前模型的专属纹理清单中随机选择另一条地址，不立即重复。远程模式继续调用已配置的PNG接口，保留原查询参数并增加独立缓存破坏参数；是否返回不同内容由接口决定。没有远程接口回退到本地的行为变更，也不从根级大型服装集合选择资源。

运行时只增加受限的纹理目标访问器和就绪事件；控制器负责解码图片、上传新WebGL纹理、成功后替换第0槽并释放旧纹理。模型、动作、渲染循环和事件监听保持同一实例。请求超过15秒、图片解码、上传或模型变化失败时释放候选纹理、保留旧纹理并允许重试；上下文丢失时不提交候选，但不能保证浏览器仍能显示原模型。上传保存并恢复GL绑定及像素状态，采用LINEAR与CLAMP_TO_EDGE支持非二次幂图片。该接口只服务现有单纹理槽Cubism2模型，不扩展到新模型格式。

## Existing record audit

[外置服装清单](../architecture/2026-10-17-live2d-external-costume-catalog.md)补充候选来源和独立配置，按钮继续复用本篇的纹理替换机制。合并候选不重置当前服装或busy；配置代次变化后旧图片响应不再提交。2026-10-17真实超时回归补充清空Image.src取消失败请求，避免同URL重试复用未结束的网络请求；120项Node和42项浏览器复验结果由该篇持有，下方87/30项保留为初始实现的历史范围。

[服装目录提案](../../proposed/feature/2026-10-17-live2d-costume-catalog.md)部分重叠，负责新增素材的兼容映射与来源，本篇只负责切换行为；[基础接入](../architecture/2026-10-07-live2d-integration.md)保留启动与861px边界，[浮层布局](../bug-fix/2026-10-07-live2d-player-layout.md)保留位置和避让。现有四项设置不变，不新增后台配置或完整服装选择面板。

## Alternatives considered

- **重调loadlive2d**：复用现有入口、改动直观；但重新请求moc和动作，且旧释放路径不能证明按纹理正确回收，不适合作为交互式换装。
- **只替换纹理（采用）**：与本次单PNG换装一致，能保留模型和动作；代价是新增受限的运行时连接与WebGL错误/资源管理回归。
- **刷新页面换装**：无需新增运行时接口，但会中断阅读和页面状态，不满足用户的便捷换装目标。

## Consequences

用户可以在阅读中切换当前模型的服装，不刷新页面，也不重新下载模型和动作。代价是受限访问器依赖当前Cubism2封装，替换运行时时需同步适配并复验GPU资源回收。当前选择不跨页面保存，整页加载仍按原逻辑随机初始化。

远程服务可能返回相同PNG或缺少CORS，本地夹具只验证处理行为，不代表真实接口可用；错误会保留旧纹理并提示重试，不自动切到本地模式。根级素材的映射、来源和首批分发清单不由按钮决定。
