# Agent Note: 导航三段断点与宽屏默认展开

Status: implemented

## Problem

861至1200px仍显示桌面导航时，菜单可能挤压换行；原“展开导航菜单”内联强制显示还会绕过中等宽度的折叠行为，造成入口与可用空间不匹配。

## Decision

保留三段行为：大于1200px使用桌面导航并受shownav默认展开设置控制；861至1200px默认收起顶部菜单，由按钮展开；不大于860px使用原左侧抽屉。

[header.php](../../../../header.php)始终输出桌面折叠按钮，以nav-default-open表达设置；[style.css](../../../../style.css)在中等断点覆盖默认展开，交互使用navbar状态。顶级菜单保持单行，限制可用宽度，并分别处理顶级透明背景和下拉子菜单背景。设置不通过全局内联important跨断点强制显示。

## Existing record audit

检索导航、断点和shownav，现有[Live2D布局](../bug-fix/2026-10-07-live2d-player-layout.md)仅使用可见页头边界，部分重叠并互链；本篇持有导航显示规则。原导航、Beta.4登录移动修复及混合修复中的相关段落归于此。

## Alternatives considered

- 继续所有桌面宽度强制展开：可维持旧开关字面含义，但会破坏861至1200px折叠和空间边界；当前把开关限定为宽屏默认状态。
- 保留原三段导航并修复状态/布局（采用）：维持已有抽屉及菜单行为。原记录只给出方案A，没有完整替代导航设计，不补造统一抽屉等比选。

## Consequences

设置语义与视口边界一致，桌面按钮始终可按断点接管；代价是三个断点区间及两类菜单结构仍需维护。超长自定义菜单和插件插入内容需要实测，不能由CSS存在性推导所有菜单都不会溢出。
