# Agent Note: 编辑页可视化封面设置

Status: implemented

## Problem

文章视频封面依赖手工填写 `cover_type`、`video_cover`、`video_cover_thumb`。经典编辑器默认隐藏自定义字段，`normal` 实际表示普通视频，读者难以发现入口。需求于2026-10-11提出，本篇于2026-10-12续接会话时成文。

## Decision

[封面编辑模块](../../../../inc/post-cover.php)在文章和页面编辑器增加“文章封面”原生 meta box，提供图片、MP4/WebM、HLS 三种类型及视频地址、视频占位图地址和媒体库选图。图片继续使用 WordPress 特色图片入口，视频占位图留空时回退特色图片；提示头部装饰图开关与特色图片前置条件。复用旧三字段，不迁移数据库、不增加第二套前端播放状态。

经典和区块编辑器共用 meta box 兼容层与宿主媒体库。资源只在文章/页面编辑页加载；不改编辑器选择、不增加 React 构建或 REST 元数据公开接口。保存验证 nonce、逐文章编辑权限、文章类型、字段形状与 HTTP(S) 地址，跳过自动保存、修订和未携带面板的请求。通过逐字段原值指纹跳过未修改输入，使旧自定义字段编辑不会被未操作的面板覆盖；改回图片保留视频地址，以便再切换。

视频输出按属性上下文转义；普通视频取消固定 MP4 MIME 提示，让浏览器按实际资源判断 WebM。旧手工元数据仍走相同渲染路径。

[前端表单脚本](../../../../inc/js/post-cover.js)对修改过的值提供即时错误提示；经典表单阻止无效提交，Gutenberg通过宿主`core/editor`保存锁阻止无效保存，修正后解除。后端仍独立验证，不能以浏览器校验替代权限/nonce。URL使用文本输入与URL键盘提示，避免浏览器对未改动的旧非法值强制校验。数据库写入后核对读回，失败通过编辑页错误通知报告；不承诺WordPress三个独立meta写入具有数据库事务性。

Gutenberg的meta box位于底部“Meta Boxes”区域，可展开和拖动分隔条调整高度。该兼容入口由[WordPress官方文档](https://developer.wordpress.org/block-editor/how-to-guides/metabox/)约束；不是新注册的专用侧栏插件。

异步保存后通过宿主`wp.apiFetch`中间件读取本面板请求的响应副本，使用返回HTML中的实际字段与指纹更新比较基准。WordPress的meta box保存不会重载当前面板，必须覆盖同页A→B→A的连续保存。同步只处理`_wpMetaBoxUrl`的POST，不影响其他请求、不执行返回脚本；保存期间新输入不被旧响应覆盖。响应携带的封面错误显示在面板内；网络失败或响应缺少完整面板时不猜测保存结果，提示重新加载并锁住后续保存，避免继续使用过期指纹。后端权限与逐字段保值契约继续独立执行。

## Existing record audit

按封面、编辑器、meta box检索活跃笔记：[HLS生命周期](../../implemented/architecture/2026-10-08-hls-loading-and-upgrade.md)部分重叠，继续约束播放和导航；[后台边界](../../implemented/architecture/2026-10-07-admin-settings-boundary.md)部分重叠，继续约束宿主依赖和存储；[首页视频](../../implemented/feature/2026-10-11-home-video-formats.md)负责独立的全站配置，本篇只增加逐文章编辑入口。三篇保留并互链，没有需要废弃的同主题提案。

## Alternatives considered

- 原生 meta box（采用）：经典和区块编辑器共用一个保存契约，媒体库由WordPress维护；代价是区块编辑器内位于兼容面板区域。
- 区块编辑器专用侧栏：位置贴近文档设置，交互更融入Gutenberg；但经典编辑器还需另一套实现，并增加REST注册和前端构建，本期不采用。
- 继续使用自定义字段并只补文档：代码维护最少，老用户习惯不变；无法解决入口隐藏及类型含义不明，保留兼容但不作为主要操作入口。
- 只记录字段曾被修改或在HTTP成功时乐观更新：实现较短，但会把一次修改永久视作脏值，覆盖之后的旧字段编辑，或把部分写入失败误当成功。本面板读取已有保存响应中的实际状态，接受一次HTML解析的成本，不增加REST公开元数据或额外请求。

## Consequences

同一保存路径覆盖两种编辑器并保留旧数据，代价是Gutenberg用户要展开宿主的底部兼容面板，且保存锁依赖宿主编辑器store。占位预览显示当前已保存的特色图片；通过其他面板换特色图片后，保存并重新加载即可同步预览。视频前台始终读取最新特色图片。

浏览器播放受编码、CORS和自动播放策略影响。源码保持3.7.0工作副本；2026-10-12版本及2026-10-13连续保存修复均已手动安装，后者于2026-10-15完成实站复验，快照ZIP及校验文件已清除。UI实测覆盖本地WordPress7.1及实站7.1.3的内置Chromium桌面与390像素尺寸模拟，真实Safari、触屏移动设备和其他第三方编辑器扩展没有覆盖。核心安装更新检查可能受隔离环境阻止外网影响，须与主题运行时日志区分。
