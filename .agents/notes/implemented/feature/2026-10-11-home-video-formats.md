# Agent Note: 首页背景视频的多格式链接与播放生命周期

Status: implemented

## Problem

2026-10-11变更前，[首页视频脚本](../../../../js/sakura-app.js)的 `Siren.addsource()` 将 `amv_url`、逗号分隔的 `amv_title` 和固定的 `.mp4` 后缀拼接。目录与无扩展名的视频名可以工作，但完整 WebM、HLS 链接会被改写成错误地址；链接中的逗号也不能安全地借用旧名称列表语法。

旧首页播放依赖 `oncanplay`，没有完整处理媒体错误、加载超时和 `play()` 拒绝。只解除扩展名限制会让 HLS 仍然无法接入，也不能防止切换视频或导航后晚到的回调重新播放。

[页头](../../../../header.php)将 `.headertop` 放在 PJAX 替换容器 `#page` 外，[头图布局](../../../../layouts/imgbox.php)在其中调用 `bgvideo()`。因此首页视频元素跨页面保留，不能沿用文章封面的 DOM 销毁假设。

## Decision

逐文章的封面编辑入口见[可视化封面面板](2026-10-11-post-cover-editor.md)，不与这里的首页全站视频列表混用。

首页使用可选的完整链接列表，同时保留旧配置回退；`createHomeVideoController()`独立管理媒体实例、播放意图与导航状态，只复用现有 `ensureHls()` 库加载入口。维护者在方案落盘后要求继续，实施范围为本地源码与隔离验证。

### Configuration contract

在[主题选项](../../../../options.php)新增 `amv_sources` 多行文本框，每行一个完整 HTTP(S) 媒体链接。说明明确：填写后优先使用此列表，留空使用原“视频地址＋视频名称”设置。

| 输入 | 处理规则 |
| --- | --- |
| 空值、仅空白行 | 使用原目录与逗号分隔名称，仍按旧约定补 `.mp4`；不迁移或重写旧字段 |
| `.mp4`、`.webm` | 使用原生 video；不为这些链接请求 HLS 库 |
| `.m3u8` | 使用首页自己的 HLS 播放路径 |
| 查询参数、片段、逗号 | 按完整链接保存，不按逗号拆分、不增删后缀；按 URL pathname 的扩展名识别类型，忽略大小写 |
| 无扩展名、其他扩展名、相对链接 | 新列表不接受；本期不增加类型标记、探测请求或 MIME 猜测 |
| 非 HTTP(S)、缺失主机、用户信息、原始控制字符或反斜杠 | 拒绝该次列表更新，显示首个错误的行号，保留原列表 |

只移除每行首尾空白、空行并统一换行；保留有效链接中的查询顺序、`&`、`+`、百分号转义与逗号。不要通过 HTML 清洗、实体解码或 URL 重新序列化改写签名内容。配置会输出给访客浏览器，后台说明提示使用可公开访问的媒体地址。服务器不预先请求媒体链接。

[选项清洗](../../../../inc/options-sanitize.php)增加 `of_sanitize_amv_sources`，复用 Options Framework 已有的字段专用 sanitizer 优先机制，不修改所有 textarea 的清洗行为。非法非空列表整组拒绝，避免随机播放集合被悄悄缩减；空列表是明确清除操作。报错信息只显示行号和格式要求，不复述完整链接。

在[主题辅助函数](../../../../inc/theme_plus.php)集中解析列表，供保存验证和前台配置构建复用；保存时出错返回旧列表。导入或直接改数据库绕过保存验证时，非空但无效的新列表输出明确的不可播放状态，不静默回退到旧视频。[脚本配置](../../../../functions.php)保留 `Poi.movies` 原有键并增加结构化来源数组与翻译文案。旧配置的正常拼接结果和相对目录行为保持兼容，忽略空名称；没有可播放来源时保留图片并给出可理解的状态。

列表继续随机选择，不增加播放顺序、媒体库上传、代理、转码或鉴权设置。`focus_amv`、`focus_height`、`head_focus` 与 `focus_mvlive` 的既有职责保持：视频关闭、全屏头图关闭或容器不存在时，不启动视频请求；首次整页打开仍由用户点击启动。播放入口支持Enter和空格，并使用翻译后的无障碍名称。

### Playback and navigation

首页拥有独立实例及初始化代数，与文章封面的 `coverHls`、`coverVideoGeneration` 隔离。MP4/WebM 直接设置原生媒体来源；HLS 按现有 MSE 优先方向复用 `ensureHls()`，不支持 MSE 时检测原生 HLS，库加载失败但原生 HLS 可用时也允许原生路径。两者均不可用则显示失败状态，不更换或升级依赖。

| 触发 | 行为 |
| --- | --- |
| 点击播放 | 选择或恢复来源，建立当前代数的监听和超时；仅当前页面仍为首页且仍有播放意图时调用 `play()` |
| 用户暂停 | 记录用户暂停意图，保留当前媒体与缓冲；返回首页也不自行播放 |
| 切换视频 | 先撤销旧监听、计时器、HLS 实例和 src，再载入新来源；晚到回调无效 |
| PJAX 替换前 | 保存来源、有效时间和播放意图，标记离页，释放首页 HLS 和原生 src，恢复图片状态 |
| PJAX 结束 | 在新 DOM 就绪后判断是否首页；`focus_mvlive` 开启且离页前仍有播放意图时恢复来源，否则保留手动播放入口 |
| 自然结束或致命错误 | 清理媒体资源，恢复图片、播放和切换入口；下一次点击可以重试 |

统一在 `pjax:beforeReplace` / `pjax:end` 接线，覆盖普通 Ajax 和缓存前进/后退。首页媒体自动恢复从 `Siren.PE()` 的早期调用中分离，原生 `popstate` 不能先于 DOM 替换决定是否播放；不重写其他组件的导航职责。离页清理不能销毁文章封面或音乐播放器实例。

为 VOD 记录离页时间，恢复时在元数据及可寻址范围就绪后恢复有效位置；直播按当前可寻址窗口恢复，不承诺回到已经移出窗口的时间。首次点击后等待库或媒体期间发生离页，同样撤销启动意图对应的异步回调；返回时按保存的意图重新初始化。开始播放时只暂停已有`ap`数组中提供`pause()`的音乐播放器，不再销毁并重建音乐实例。

每次启动设定 30 秒的首帧等待上限，进入 `playing`、被用户取消、被导航替换或失败后取消计时器。`play()` 被浏览器策略拒绝时立即恢复手动入口；原生媒体错误、HLS fatal error 或超时均进入可重试状态。HLS 自身的有限网络恢复保留，主题不额外无限重试。失败提示区分加载失败与需要再次点击播放，不能一直隐藏按钮或停在“正在载入”。

手动暂停保留缓冲，可能继续下载到播放器自身的缓冲上限；离页则销毁并停止当前媒体来源。选择离页重建而不是保留 HLS 实例并组合 `stopLoad()` / `startLoad()`，是为了统一处理库加载中、manifest 未就绪、正常播放和缓存返回，减少中间状态。

### Scope and implementation surfaces

- `options.php`、`inc/options-sanitize.php`、`inc/theme_plus.php`、`functions.php`：配置、纯解析函数、前端数据和提示文案；不改 Options Framework 的通用保存流程。
- `js/sakura-app.js`：首页控制器、现有 Siren 按钮接线与相关导航钩子；复用库加载函数，不合并文章封面与音乐的实例状态。
- `scripts/tests/home-video.test.cjs`：执行实际首页逻辑的异步、状态和导航测试；现有 `scripts/tests/hls.test.cjs` 保留回归。
- `scripts/wordpress-smoke.php`、`scripts/tests/README.md`：真实选项清洗、读取及前端配置验证与测试说明。
- `languages/sakura.pot` 及 `zh_CN`、`zh_TW`、`en_US`、`ja` 的 PO/MO：新增字段、错误与播放状态翻译，使用现有编译方式。
- `scripts/compile-translations.php`：本轮真实WordPress读取发现空哈希表偏移为0的兼容缺陷；编译器改为有效空表位置并重新生成四语言MO。现行格式理由与真实读取测试见[兼容性验证](../testing/2026-10-07-compatibility-evidence.md)。

本期不改变文章封面配置、不升级 hls.js、不扩展 Live2D，不自动保存测试站设置。站点部署与实站配置验收沿用维护者确认的交接方式，实施批准仅覆盖本地源码和隔离验证。

## Alternatives considered

- **扩展原两个字段语法**：后台变化最小，原用户无需学习新入口；但完整链接中的逗号、尾斜杠、扩展名和目录拼接形成多种解释，增加猜测规则，不能清楚表达新旧优先级，因此不采用。
- **新增可选的每行完整链接列表（采用）**：来源格式明确，能保留查询参数并让旧配置原样继续使用；代价是后台多一个字段，需要清楚标注优先级并测试两个输入路径。
- **统一重写首页、文章封面和音频播放层**：可以统一错误处理与资源管理；但三个消费方的 DOM 生命周期、控件和播放意图不同，会扩大已验收封面与音乐的回归面，本阶段不采用。
- **离页保留 HLS 实例并停止加载**：返回时可能复用缓冲，减少重新初始化；但还需单独处理 manifest 请求中断、库尚未就绪和已经失效的回调。本期保存来源与时间后销毁，接受返回时重新加载的成本。

## Consequences

容器支持不等于编解码器支持，HLS 还受 CORS、媒体服务器 MIME、浏览器策略与网络质量影响。仅凭后缀不保证地址可播放；失败应能恢复操作，不在主题内转码或绕过服务器限制。

离页销毁会丢弃缓冲，返回可能增加流量并出现短暂等待；签名地址可能在返回前过期。直播窗口与点播时间轴不同，精确恢复只承诺有效、可寻址的点播位置。无扩展名接口以后若有实际需求，再评估显式类型字段，不在本期猜测。

2026-10-11对现有 hls.js 1.7.3 文件完成离线能力探针：SHA-256 为 `a12e7ee1cd64a69dcdb314157e45dafcba705bfb0b1440b7935cb265d374423e`，与现行 HLS 笔记记录的官方发行文件一致；`loadSource`、`attachMedia`、`on`、`destroy`、`startLoad`、`stopLoad` 均存在，创建后销毁使网络控制器由10变为0，核心组件为0、媒体引用为null。没有 MSE 的 Node 环境不支持播放，此结果只验证清理接口，不证明浏览器解码。
