# Agent Note: 扩展服装与主题安装包分开存放

Status: implemented

## Problem

维护者在2026-10-17提出WordPress主题上传大小限制，要求确定后续服装的接入方式。每次主题更新都携带全部纹理，会增加上传、下载和备份体积；直接把额外文件放进主题目录，还可能在主题替换升级时丢失。这里需要解决扩展素材的交付与持久存放，无需因此更换Cubism运行时。

[原服装提案](../../proposed/feature/2026-10-17-live2d-costume-catalog.md)已完成模型映射，最初倾向少量服装随主题分发。本篇在新增包大小约束下改变分发方式；映射结果、候选清单及来源限制继续由原篇负责。维护者于2026-10-17明确“确定执行”，批准同站点独立目录＋静态清单首期；没有部署服装服务或分发新增图片。

## Decision

主题保留基础纹理，扩展服装使用独立目录和静态清单。首期优先使用站点自己的上传目录，设置项 `live2d_catalog` 接收可选服装清单地址；有现成对象存储/CDN时可部署同样的静态文件。主题安装包只增加加载代码、说明与回归源码，新增PNG不进入主题包。部署步骤与完整格式见[使用说明](../../../../live2d/README.md)。

### 上传限制与体积依据

WordPress没有适用于所有自托管站点的统一主题ZIP上限。[wp_max_upload_size](https://developer.wordpress.org/reference/functions/wp_max_upload_size/)取PHP的upload_max_filesize与post_max_size较小值，再经过upload_size_limit过滤。[PHP说明](https://www.php.net/manual/en/ini.core.php#ini.post-max-size)要求POST总量为文件和表单开销留空间；[Nginx client_max_body_size](https://nginx.org/en/docs/http/ngx_http_core_module.html#client_max_body_size)还可能提前以413拒绝请求。主机平台和多站点配置也可能施加限制；过滤WordPress显示值不能突破服务器限制。实际值应在目标站点后台与服务器配置核对，不能从其他站点或本机PHP推定。主题目录提交审核和WordPress.com套餐限制是不同问题。

构建84的已验证主题ZIP为15,796,123字节（约15.06MiB）。2026-10-17直接读取现有PNG，在内存中使用ZIP Deflate level 6测算，没有重新生成或保存安装包：

| 素材范围 | 原始PNG | 独立ZIP测算 | 加到当前主题的体积估算 |
| --- | ---: | ---: | ---: |
| 原提案建议的5套 | 2,633,148字节 | 2,566,827字节，约2.45MiB | 约17.51MiB |
| 根级107套 | 52,094,336字节 | 50,636,337字节，约48.29MiB | 约63.36MiB |

合并值只是当前包加素材ZIP的估算，不是正式构建结果；路径、ZIP元数据、清单和代码变化会改变实际值。全量估算包含3份内置重复素材，实际接入应去重。16MiB上传限制下，连5套方案也可能超限；调高单个站点限制不能保证其他用户的环境。PNG已压缩，ZIP再次压缩收益有限；WebP或缩小纹理可另行评估视觉质量，不能直接作为无损或完全兼容的替代。

截至2026-10-17，WordPress.org主题目录的[官方上传实现](https://github.com/WordPress/wordpress.org/blob/trunk/wordpress.org/public_html/wp-content/plugins/theme-directory/upload.php)明确返回 `10 * MB_IN_BYTES`。这属于目录投稿入口；未找到WordPress统一50MB上限的依据，也未读取维护者测试站的实际上限。

### 存放与部署

- 主题继续提供Tia/Pio各自的三套基础纹理；未配置扩展目录时行为不变。
- 默认目录示意：相对于WordPress安装目录的 `wp-content/uploads/sakura-live2d/pio/pack-v1/`，包含静态JSON清单和PNG。后台只显示通用目录和通过[wp_upload_dir](https://developer.wordpress.org/reference/functions/wp_upload_dir/)的baseurl生成的清单网址，不输出basedir的服务器磁盘绝对路径。自定义上传目录与多站点以站点配置为准；网址是否包含子目录由安装位置决定，主题名称不会固定增加 `/sakura/` 前缀。
- 首期由维护者通过SFTP、服务器文件管理器或已有静态存储工具放置文件。目录独立于主题替换，但需纳入站点备份；不能承诺所有主机或清理插件永久保留它。
- 只有WordPress后台上传能力时，可考虑按本站限制拆分小包或另案实现受控导入。通过同一PHP入口上传独立ZIP仍受相同限制；服务端下载也有网络、超时、磁盘与校验成本，首期不增加下载/解压管理器。
- 对象存储/CDN使用版本化目录与稳定地址。跨域清单和PNG均须允许站点读取，PNG还需满足WebGL纹理CORS要求；能直接打开图片不等于可作为纹理使用。密钥不进入前端，浏览器直接请求公开静态资源，不新增PHP任意URL代理。

### 加载与失败行为

1. 启用看板娘且宽度达到861px时，先由现有本地loader加载内置模型和服装。扩展清单异步读取，网络不可用不阻塞基础模型显示。
2. 清单包括格式版本、服装包版本、模型身份/模型哈希以及逐项ID、相对PNG路径。只把符合当前模型的有效、去重条目加入扩展候选池。未知格式、错误模型、空清单、路径越界或非法协议拒绝接入；不携带可执行脚本。
3. [现有控制器](../../../../live2d/js/costume.js)继续处理换装和纹理释放。候选合并保留当前服装与busy状态，不能用初始服装重新调用configureCostumes覆盖用户刚完成的切换；重复初始化不重复合并，迟到的旧清单不影响新模型或新配置。
4. 首屏只加载一张内置纹理，换装时请求一张选中的PNG，不预下载完整服装包；允许浏览器缓存已经访问的固定素材。
5. 清单超时、404、格式或CORS失败时继续使用内置服装；单张PNG失败时保留当前纹理并允许重试。这是新清单模式的容错，不修改已有远程随机PNG模式的初始加载契约。
6. 内容更新使用新版本目录/地址，切换配置后验收；固定PNG不加每次变化的随机参数。旧目录由部署维护者在使用结束后清理，主题升级不得自动删除用户素材。

现有“远程服装”选项接收单张PNG或随机PNG接口；静态清单使用独立配置，不能把JSON地址填入旧输入框或静默改变其含义。前台复用现有换装按钮，首期不增加商城、复杂选择器或通用下载器。

### 当前格式与实施范围

清单固定 `version: 1`，必填 `packVersion`、`model.id`、`model.sha256` 和 `costumes` 数组。最大64KiB、256项；ID/包版本为最长64字符的ASCII标识，PNG相对路径最长240字符。路径只能位于清单目录内，不允许协议、百分号编码、反斜杠、查询或片段。相同条目/URL去重，同ID不同路径或任一非法条目整包拒绝；不根据相同字节内容跨URL去重。

[catalog.js](../../../../live2d/js/catalog.js)使用10秒有界XHR获取清单，拒绝重定向、HTTPS页面的HTTP地址及过量响应；版本目录负责缓存失效，包版本本身不改写PNG URL。PHP从当前模型文件计算指纹，保存时只校验地址格式，不探测外部网络。

loader使用配置键和请求状态避免重复初始化及过期响应；`configureCostumes`返回代次，`mergeCostumes`只合并同代次候选，保留current与busy。纹理失败/15秒超时后清空Image.src，取消旧请求，防止浏览器重试同URL时继续等待原请求；旧代次图片响应不提交纹理。

测试夹具只复用现有已分发纹理。新增素材名单确认后再接入原提案候选，来源与分发依据独立确认；CDN存放不会改变这项边界。后台“从CDN下载到本地”由维护者明确作为探讨，未纳入本次实现。

## Alternatives considered

- **少量服装随主题分发**：安装步骤最少且没有外网依赖，适合数量长期稳定、包上限宽松的站点；5套已可能把当前包推到17.51MiB，后续扩充继续增大主题，不作为本次长期推荐。
- **同站点独立目录和静态清单（推荐首期）**：基础主题大小基本不随服装数增长，没有跨域配置，主题替换不触碰该目录；代价是独立部署和备份素材，并维护目录权限及版本切换。
- **对象存储/CDN静态清单**：不占WordPress主机空间，便于缓存和多站点共用，已有存储时合适；需要维护域名、CORS、可用性和流量成本。为少量服装新建整套服务未必划算，同一清单契约允许之后更换存放位置。
- **WordPress后台ZIP导入/服务端下载**：管理员操作方便；ZIP上传仍有限制。服务端逐文件下载通常不经过浏览器上传ZIP的限额，但仍需权限/nonce、可信源及重定向约束、文件哈希、下载超时、体积/磁盘限制和失败回滚。可复用清单并在完整校验后启用新目录；维护者明确这只是探讨，确有需要再设计受控下载，不新增后台按钮。
- **仅提高PHP/Nginx上限**：对完全控制的测试站最直接；不减少下载与更新体积，也不能代替其他使用者修改主机限制，作为部署配置处理。
- **复用随机PNG服务**：没有新增清单协议；无法提供固定候选身份、包版本及逐项兼容映射，保留现有选项而不承担目录职责。

## Consequences

独立存放减少主题包体积，却新增素材部署和备份工作。CDN故障、配置清理或旧目录被删可能减少可选服装；内置样本保证基本显示，不能保证每个扩展条目永久可用。

清单增加一个可选网络契约与独立素材部署步骤，默认空配置不获取清单。固定资源便于缓存，但错误响应被缓存时需清理缓存或切换版本URL；主题不自动删除用户目录。首批新增服装、后台下载/导入、图片格式转换及运行时升级继续独立评审。
