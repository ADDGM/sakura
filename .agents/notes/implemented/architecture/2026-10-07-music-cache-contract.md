# Agent Note: 播放器站点签名、缓存与网易云音频协议

Status: implemented

## Problem

访客登录状态变化会使旧歌单中的会话 nonce 失效；长缓存又可能保留失效音频地址。网易云返回的部分歌曲地址为空，强行改写协议也曾导致局域网音频无法播放。维护播放器时需要区分站点音乐配置、访客会话和上游资源可用性。

## Decision

保留播放器设置键和 `/sakura/v1/meting/aplayer` 路径。[inc/api.php](../../../../inc/api.php) 使用站点级 `music_token`，以 HMAC 绑定版本、平台、类型、资源 ID、到期时间及音乐配置指纹。音乐 Cookie 只供服务端访问上游，公开 token 中是指纹；不得把 Cookie 明文写入页面、响应、日志或缓存键。

只有有效 token 且没有旧 nonce 参数的请求进入公开缓存路径，403、502 使用不可缓存响应。原过渡策略曾允许 `meting_nonce`、`_wpnonce` 或 `X-WP-Nonce` 通过旧校验进入 private/no-store 路径，混合请求也不升级为公开请求。维护者确认没有外部旧客户端后，该过渡策略于2026-10-15由[音乐接口只接受站点签名](../simplification/2026-10-15-music-token-only.md)部分替代：非空旧 nonce（包括混合有效 token）一律拒绝。本篇的签名、TTL 和上游音频契约继续有效。

公开响应和 [Aplayer](../../../../inc/classes/Aplayer.php) Transient 的基础缓存时间分别为：歌单300秒、歌词1800秒、封面3600秒、音频15秒。公开响应还含 `stale-while-revalidate=60`，因此15秒不是所有中间缓存的绝对存活上限。token 有效期分别为7天、1天、1天、1小时，与缓存 TTL 不同；源站重新验证时配置指纹改变会使旧 token 失效，已缓存响应则仍受缓存策略约束。

音频保持301重定向和上游直传。[Meting::netease_url](../../../../inc/classes/Meting.php) 仅在 `uf.url` 是有效 HTTP(S) 地址时采用它，否则保留有效的 `data.url`。网易云地址不强制改写协议或 CDN 主机；其他平台已有处理保留。缺少歌曲详情时按 trackIds 顺序补取缺项，不把歌单部分返回误判成仅有一首歌。

## Existing record audit

已检索播放器、token、缓存和网易云。[浮层位置](../bug-fix/2026-10-07-live2d-player-layout.md)只涉及前台遮挡；[核心资源](2026-10-07-core-resource-policy.md)只涉及静态文件来源。本篇与它们部分重叠并互链，不复制布局或资源版本决定。三个播放器专项和兼容性总计划相关段落合并于此。

## Alternatives considered

- 保留会话 nonce：兼容旧缓存、旧脚本和自定义 meting_api，但无法作为跨登录状态公共缓存的唯一协议；当时采用私有兼容入口作为过渡，退出条件及当前行为见上述新决定。
- 音频改为307加no-store并取消两层缓存：可减少短期过期地址滞留，但原音频错误计划明确将它移出批准范围，保留301与15秒缓存。历史未完整记载拒绝理由，不补造性能测量。
- 强制网易云 HTTP 升级为 HTTPS：可避免浏览器混合内容，但曾破坏目标 CDN 的实际播放链路，故保留合法原协议。服务端音频代理未获实施批准。

## Consequences

站点配置可供匿名与登录访客使用，token 过期与多层缓存仍需共同维护。原过渡阶段的双授权入口已按新决定收敛，旧缓存页面需刷新。保留原协议不保证 HTTPS 页面接受 HTTP 音频，301与上游短效地址也可能引起个别播放失败；中文错误提示不代表上游权限或服务故障已修复。

## Verification

2026-10-07按 `2a42534` 核对 token、请求分流、缓存头、Transient、URL选择和歌单补全源码。本篇日期是维护契约成文日，不推定原功能首次提出日。Beta.4原验收记录有匿名歌单、56条入口及真实播放证据；本轮未请求网易云、读取实际 Cookie或重跑播放测试。

### First-play investigation 2026-10-16

运行基线快照部署验收的首次 M18 播放曾触发 `NotSupportedError` 并自动切曲，刷新后恢复。后续独立 Chromium 的初次加载、常规缓存重载、禁用浏览器缓存重载三个样本均播放至 2–3 秒，媒体 readyState 为 4、error 为 null；歌单 200、音频 301 后上游 206 audio/mpeg，无音乐 403/502。Codex 内置浏览器另一个新首页样本从 00:00 播至 01:51，56 首歌单，notice 为空且 opacity 为 0，捕获的 error/warn 为空；两种浏览器的证据分别记录，不混作原失败请求。

这些成功样本未复现原故障，不能证明根因修复或缓存无缺陷；禁用浏览器缓存也不等于关闭服务端及代理缓存。一次 canceled=true 的 ERR_ABORTED 后续得到 Range 206 并正常播放，不作为播放失败。原故障只记录提示文本、未记录可见性，不能据此认定提示残留；[提示本地化](../../../../js/aplayer-localization.js)只翻译消息，不改变 APlayer 的 notice 生命周期。

原失败请求的状态、MIME、重定向链、媒体错误及缓存来源仍缺失。后续再次失败时需在刷新前对齐这些信息与曲目和时间，并只记录 token 到期与参数匹配结果，不保存完整签名地址或 Cookie。现有证据不足以调整缓存、增加音频代理或改写上游协议，本篇运行契约保持不变。
