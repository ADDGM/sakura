# Agent Note: 核心资源本地默认与旧远程选项兼容

Status: implemented

## Problem

主题核心 CSS/JS 曾通过上游仓库拼接维护版标签和不存在的压缩文件路径，造成默认配置下资源加载失败。PHP 入队和前端动态 CSS 如果分别拼接地址，还会产生来源与缓存版本不一致。维护时需要保留用户已保存的本地/远程选择，并区分核心资源、可选增强与用户自定义服务。

## Decision

核心资源以主题包内文件为默认来源。[functions.php](../../../../functions.php) 的 `sakura_core_resource_is_local()` 将缺省值视为本地，仅把旧设置的明确关闭值 `false`、`0`、`'0'` 解释为远程。`jsdelivr_cdn_test` 与 `app_no_jsdelivr_cdn` 继续作为兼容输入，不通过迁移数据库反转用户选择。

`sakura_core_resource_url()` 统一解析资源地址，`sakura_scripts()` 和 [inc/swicher.php](../../../../inc/swicher.php) 的 `font_end_js_control()` 共用它。缓存版本由 `sakura_frontend_cache_version()` 生成，即主题版本加 `cookie_version`；动态 CSS 与 PHP 入队共用这个来源。

远程核心资源使用 `ADDGM/sakura` 的明确标签和实际存在的文件。当前 `SAKURA_REMOTE_RESOURCE_TAG` 默认值是 `v3.5.0`，不是早期资源冻结记录中的 `v3.5.0-beta.7`。`sakura_remote_resource_tag` 过滤器可覆盖标签，现有实现清理非法字符并对空值回退默认值；它不查询标签是否真实发布，不应被描述为发布存在性校验。

## Network boundary

本地默认只约束核心资源。Google Fonts、图标字体、APlayer 增强样式、头像和音乐平台仍可能发起网络请求；用户自定义背景、CDN 和上传 API 不属于主题自动镜像范围。核心解析器在用户明确选择远程后不会在网络失败时自动切回本地，因此不能把“默认本地”写成“远程请求失败自动重试本地”，也不承诺整站完全离线运行。

## Existing record audit

创建前检索核心资源、远程资源、旧设置和缓存，没有可承接此契约的活跃 Note。[Live2D 接入](2026-10-07-live2d-integration.md)复用这里的缓存与本地资源原则，属于部分重叠，互链保留模块职责。提交、发布及通知笔记不接管运行时资源地址解析。

后续历史提炼的[播放器缓存](2026-10-07-music-cache-contract.md)与[后台设置边界](2026-10-07-admin-settings-boundary.md)部分重叠，分别持有音乐响应缓存和后台渲染/旧CSS映射，不扩大本篇的静态核心资源范围。

## Alternatives considered

- **主题仓库提供远程资源（采用）**：发布文件和版本在一个仓库中维护，无须第二套同步链路；代价是远程资源版本与主题发布耦合，必须维护可用的明确标签。
- **独立资源仓库（保留为后续选择）**：资源可独立更新和发布，但当前需要额外维护仓库与同步流程。只有资源更新节奏与主题明显分离时才重新评估。

这两个方案来自原资源治理记录。本篇不将所有旧外链都归为当时主动选择保留的方案，也不补造未记录的选型理由。

## Consequences

本地核心文件减少对上游标签和失效图床的依赖，统一解析避免 PHP 与动态 CSS 分叉；代价是主题包需要携带资源副本，旧开关的反向语义继续存在。第三方许可、可选资源的失败表现和远程标签维护仍需分别处理，旧依赖整理不能擅自删除兼容读取。
